# Dar Zayna

Website for a Moroccan restaurant, in **French** (default), **Arabic** (right-to-left) and **English**, with a contact form that emails the restaurant.

> **Demo project.** Dar Zayna is a fictional restaurant, built to show what the studio can make for a real one. Every page says so, search engines are asked not to index it, and the contact details are placeholders. See [Turning the demo into a real restaurant site](#turning-the-demo-into-a-real-restaurant-site).

## What is in it

- **Five pages in each language:** Home, Menu, About (*La maison*), Gallery and Contact, plus a 404 page. French at `/`, Arabic at `/ar/`, English at `/en/`.
- **Menu:** 22 dishes in six categories, each with prices in dirhams, vegetarian marks and photos. A category filter works with shareable links (`/menu/#tagines`).
- **Gallery:** 12 photos with an accessible lightbox. Arrow keys follow the reading direction, and the gallery works without JavaScript.
- **Contact form:**
  - The browser checks the fields, and the server checks them again with Zod.
  - It has a honeypot against spam bots, rate limiting (5 messages per 15 minutes per IP address) and an HTML-escaped email template.
  - The form only says "sent" when the email service confirmed it. If sending fails or isn't configured, the visitor is told so and pointed to WhatsApp.
  - Nothing the visitor types is stored or logged.
- **Table requests** go through the contact form and are clearly presented as requests, never as confirmed bookings.
- **WhatsApp button** with a pre-filled message.
- **Accessibility:**
  - Semantic HTML, a skip link and visible keyboard focus.
  - Text contrast checked against WCAG AA, and the form's errors are linked to their fields.
  - Reduced motion is respected.
- **Performance:**
  - Responsive WebP images in three sizes, lazy-loaded below the fold.
  - Self-hosted fonts and no third-party scripts.
  - CSS and JS files are fingerprinted so browsers can cache them.
- **Security:**
  - Helmet headers, with a strict Content Security Policy (no inline scripts or styles).
  - A 10 kB limit on request bodies, and secrets come only from environment variables.

## Tech

| Part | Technology |
| --- | --- |
| Pages | HTML5, CSS3, vanilla JavaScript; generated by `frontend/build.js` (Node, no dependencies) |
| Server | Node.js 22, Express 5, Zod 4, Helmet 8, express-rate-limit 8 |
| Email | [Resend](https://resend.com) HTTP API, called with Node's built-in `fetch` |
| Tests | Node test runner (backend), Playwright + axe-core (browser) |

## Run it locally

You need Node.js 22 or newer.

```bash
npm install
```

```bash
cp .env.example .env
```

```bash
npm run dev
```

Open http://localhost:3000. Without email settings in `.env` the site works, and the contact form honestly answers that sending is not switched on yet.

| Command | What it does |
| --- | --- |
| `npm run build` | Generates the site into `dist/` |
| `npm start` | Starts the server (run `npm run build` first) |
| `npm run dev` | Builds, then starts the server and restarts it when backend files change |
| `npm test` | Runs all tests: backend first, then the browser tests |
| `npm run test:backend` | 29 API, validation, email and security tests |
| `npm run test:e2e` | Builds, then runs 69 Playwright tests in Chromium |

The first time, Playwright may need its browser: `npx playwright install chromium`.

## Contact API

`POST /api/contact` with a JSON body:

```json
{
  "name": "Salma Benali",
  "email": "salma@example.com",
  "phone": "+212 6 12 34 56 78",
  "subject": "reservation",
  "message": "A table for four on Saturday at 8 pm.",
  "language": "fr",
  "website": ""
}
```

**Fields:**
- `phone` is optional.
- `subject` is one of `reservation`, `event`, `information`, `other`.
- `language` is `fr`, `ar` or `en`.
- `message` is 10 to 2,000 characters.
- `website` is the honeypot and must be empty.

**Answers** (always JSON):

| Status | Body | Meaning |
| --- | --- | --- |
| 200 | `{ ok: true }` | Resend accepted the email |
| 400 | `{ ok: false, error: "validation", fields: [...] }` | Invalid fields, by name |
| 400 | `invalid_json` / `rejected` | Malformed body / honeypot filled |
| 413, 415 | `too_large` / `unsupported_media_type` | Body over 10 kB / not JSON |
| 429 | `rate_limited` | Too many messages from this IP |
| 502 | `email_failed` | Resend refused, timed out or was unreachable |
| 503 | `email_not_configured` | Email settings are missing |

## Turning the demo into a real restaurant site

1. **Details:** edit `frontend/src/data/site.js` (phone, WhatsApp number, email, address, hours), then set `demo: false`. This removes the demo banner and labels, makes the phone and email clickable, and allows search engines to index the site (`robots.txt` and `sitemap.xml` are generated).
2. **Menu:** edit `frontend/src/data/menu.js` (dishes, prices in MAD, photos).
3. **Text:** edit `frontend/src/i18n/fr.js`, `ar.js` and `en.js`. The build stops with a clear message if a language is missing a key.
4. **Photos:** put the restaurant's own photos in a folder, named like the current ones (for example `tagine-prunes.jpg`), then run `python3 scripts/optimize_images.py <folder>`.
5. **Address:** set `SITE_URL` to the real domain, used for canonical links and social previews.
6. **Check:** run `npm test`.
